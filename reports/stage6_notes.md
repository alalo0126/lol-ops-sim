# 6단계 메모: 천상계 정글러와 학습 정글러 비교

2026-10-20. 자동 생성 표는 [stage6_compare.md](stage6_compare.md), 수치 원본은 `stage6_compare.json`.

## 결론

1단계 실제 999판의 양 팀 정글러 3~17분 상황 28,880개를 시뮬레이터 상태로 옮겨 학습 정글러(5단계 최종 정책)에게 다음 1분을 고르게 했다.

- **고르는 운영은 크게 다르다.** 학습 정글러는 라인 개입(갱·합류) 51% / 오브젝트 27% / 우리 정글 12% / 카정 3% / 귀환 2%, 실제 천상계는 25% / 16% / 23% / 11% / 18%다.
- **그런데 시뮬레이터 안에서도 그 차이가 이득이 아니다.** 같은 실제 상태에서 첫 1분만 천상계가 실제로 한 범주로 묶고 이후는 학습 정글러가 두게 하면, 처음부터 학습 정글러가 고른 것보다 20분 예측 승률이 **−0.4%p (95% CI −0.9~+0.0)** 낮을 뿐이다. 차이 지점 15쌍 중 13쌍은 시뮬 안에서도 우열이 없다.
- 5단계의 큰 우위(규칙 봇 대비 +0.31)는 "천상계보다 나은 1분 선택"에서 나온 것이 아니라, 규칙 봇 상대와 시뮬레이터 가정 위에서 쌓인 것으로 본다.
- 원인 분류: 더 나은 전략 후보 1건(캠프 대신 오브젝트, 근거 약함), 시뮬레이터 오류 4건(카정 가치, 귀환 가치, 라이너 체력, 오브젝트 대신 캠프 1쌍), 조건 차이 1건(캠프 타이머를 알 수 없어 우리 정글을 덜 돎), 나머지는 시뮬 안에서도 우열이 없어 판정 보류. 아래 표.

## 방법

| 단계 | 내용 | 파일 |
|---|---|---|
| 원본 줄이기 | PC `data/raw` 900MB → 분 프레임·킬·에픽 몬스터·구매만 7MB | `tools/stage6_compact.py` |
| 범주 붙이기 | 다음 1분의 위치·이벤트로 6개 범주. 실제와 시뮬에 **같은 함수**를 씀(우선순위: 에픽 몬스터 관여 > 킬·사망 위치 > 구매 > 1분 뒤 위치) | `sim/stage6.py` `label`, `zone` |
| 상태 옮기기 | 실제 분 프레임의 위치·체력·레벨·경험치·골드·CS·킬, 오브젝트 처치 기록 → 시뮬 상태. 예측 승률은 실제 값과 정확히 같음(테스트) | `reconstruct` |
| 1분 선택 | 상황마다 학습 정글러 2회, 규칙 봇 1회 1분 실행 | `python -m sim.compare situations` |
| 반사실 | 표본 1,622개 상황(시기 × 드래곤 상태 × 실제 범주 칸마다 최대 25개, 칸 크기로 가중). 첫 행동을 범주 6개 중 하나로 묶은 것 + 자유, 각 8회 20분까지 | `python -m sim.compare counterfactual` |
| 가정 바꿈 | 표본 975개 × 6회. 가정을 그대로 둔 같은 난수 반복(repeat)과 짝지어 비교 | `--set`, `--camp-shift`, `--tag` |

상태 옮기기에 들어간 추정(실제 타임라인에 없는 값): 캠프 타이머(1분 단위 정글 CS 증가를 위치가 가까운 캠프에 배정), 점멸 모두 있음, 웨이브 0.5, 와드 없음, 강타 1충전, 적 정글러는 지금·1분 전 위치가 우리 시야 노드면 본 것으로.

반사실 실험의 1차 결과(범주로 1분 내내 묶음)는 귀환으로 묶으면 우물에서 귀환만 되풀이하는 실험 오류가 있어 버렸다. 지금은 묶은 범주 행동을 한 번 끝내면 풀어 준다(시작 비율 100%).

## 차이 목록과 원인 분류

시뮬 반사실은 학습 쪽 − 실제 쪽 20분 예측 승률(%p). 실제 대조는 같은 시기 실제 정글러가 학습 쪽 범주를 한 1분 − 실제 쪽 범주를 한 1분의 (최종 승리 − 예측 승률). 범주가 1분 동안의 킬·사망·에픽 처치로도 정해져(결과가 섞임) 실제 대조는 방향 참고용이다.

### 범주 단위

| 차이 | 실제 → 학습 | 시뮬: 그 범주로 묶은 1분 (자유 대비) | 실제 대조 | 분류 | 근거 |
|---|---|---|---|---|---|
| 카정을 거의 안 함 | 11% → 3% | −1.7%p (−2.2~−1.2), 가정 5개를 바꿔도 같음 | 카정한 1분의 초과 승률 +0.2~+2.3%p, 우리 정글 −3.1~+0.3%p | **시뮬레이터 오류** | 시뮬은 카정을 확실히 손해로 보는데 실제로는 손해가 아님. 5단계에서 의심한 "카정 보상 모델 약함"과 같은 방향. 적 정글러 위치를 알고 들어가는 실제 카정과 달리 시뮬은 적 캠프 생존을 모르고 감 |
| 귀환을 거의 안 함 | 18% → 2% | −0.5%p (−1.0~+0.1) | 귀환한 1분 −1.5~−3.3%p(싸움에 진 뒤 귀환하는 선택 편향) | **시뮬레이터 오류(구조)** | 시뮬에서 아이템은 캠프 처치 속도와 신발에만 쓰이고 갱·교전에는 안 들어감. 승률 모델도 골드 총액만 봐서 산 것과 안 산 것이 같다. 아이템이 교전에 들어가게 바꿔도(천 골드당 레벨 1 차이, 가정) 귀환 가치가 거의 안 변해 이 모델로는 귀환의 값을 잴 수 없음 |
| 라인 개입이 2배 | 25% → 51% | −0.2%p (−0.6~+0.3) | 라인 개입 1분 +0.8~+1.6%p(킬이 범주에 섞임) | **시뮬레이터 오류(학습 환경)** | 실제 상태에서는 갱이 다른 선택보다 낫지 않다. 시뮬 경기의 라이너 체력이 실제보다 낮아(중앙 0.66 vs 0.91, 50% 미만 35% vs 15%) 학습 중에 갱이 실제보다 잘 통했던 것으로 봄(추정). 딜교환 자리표시 값을 [0.01, 0.08], 회복 0.003으로 바꾸면 실제 분포(10%·25% 지점 0.41·0.60 vs 실제 0.41·0.66)에 맞음 |
| 초반 오브젝트 대기 | 3-5분 3% → 23% | 3-5분 −1.8%p (−2.8~−0.8) | - | 판정 보류 | 시뮬도 오브젝트로 묶는 것을 손해로 봄. 드래곤 5:00 생성 전에 둥지로 가는 습관으로 보이며 학습 정책 쪽 문제 |
| 우리 정글을 덜 돎 | 23% → 12% | −0.5%p (−0.8~−0.2) | - | **조건 차이** | 실제 상태에서 시뮬 정글러의 1분 정글 CS가 4.6으로 실제 7~8보다 적다. 캠프 타이머를 1분 이르게 추정하면 6.0. 1분 단위 프레임으로는 캠프 타이머를 알 수 없어 옮긴 상태의 캠프가 실제보다 적게 살아 있는 것으로 봄 |

규칙 봇도 실제 상태에서는 라인 개입 48%, 우리 정글 15%로 학습 정글러와 비슷하게 치우친다(귀환은 14%로 실제에 가까움). 라인 개입 쏠림의 일부는 옮긴 상태(캠프가 적게 살아 있음)와 규칙 봇 상대라는 조건에서 온다.

### 상황 단위 (같은 실제 상태에서 학습 정글러가 다르게 고른 쌍, 비중 상위)

| 실제 → 학습 | 비중 | 시뮬 반사실 | 실제 대조 | 분류 |
|---|---|---|---|---|
| 우리 정글 → 라인 개입 | 16% | +1.0 (−0.0~+2.1) | +2.7 | 판정 보류 |
| 귀환 → 라인 개입 | 13% | −0.8 (−1.9~+0.4) | +4.0 | 판정 보류 |
| 카정 → 라인 개입 | 8% | +0.4 (−0.7~+1.4) | −0.2 | 판정 보류 |
| 오브젝트 → 라인 개입 | 8% | +0.6 (−0.7~+1.9) | −2.6 | 판정 보류 |
| 우리 정글 → 오브젝트 | 8% | +1.7 (+0.1~+3.4) | +5.7 | **더 나은 전략 후보** (실제 대조는 에픽 처치가 범주에 섞여 과대) |
| 라인 개입 → 오브젝트 | 7% | +0.1 (−1.4~+1.7) | +2.7 | 판정 보류 |
| 오브젝트 → 우리 정글 | 2% | +2.0 (+0.1~+4.0) | −5.7 | **시뮬레이터 오류 후보** (원인 모델 미확인) |

전체 15쌍은 `stage6_compare.md` "차이 지점 목록". 가정 바꿈 5개(적 정글의 오브젝트 다툼, 갱 성공률, 라이너 체력, 캠프 타이머, 아이템 효과) 중 어느 것도 상황 단위 차이를 유의하게 절반 이하로 줄이지 않았다.

### 결과 모델 대조 (그 범주로 붙은 1분에서, 실제 / 학습 정글러)

- 라인 개입 1분의 킬 관여 74% / 70%, 사망 27% / 23%: 갱 한 번의 결과는 실제와 비슷하다. 다른 것은 횟수다.
- 오브젝트 1분의 에픽 처치 88% / 83%.
- 카정 1분의 킬 관여 53% / 84%: 시뮬 카정은 거의 매번 교전이 된다(조우 교전 모델이 가까우면 확률적으로 싸움).
- 1분 수입은 실제 상태에서 시뮬 쪽이 낮다(골드 390~543 vs 학습 361~406). 정글 CS 차이(위 조건 차이)와 킬 골드 차이.

## 한계

- 실제 쪽 "선택"은 1분 뒤 위치와 이벤트로 붙인 범주다. 같은 1분 안의 여러 행동(귀환 후 갱)은 하나로 뭉개진다.
- 실제 대조는 관찰 값이라 선택 편향이 크다(싸움에 진 뒤 귀환, 킬이 나면 라인 개입으로 붙음). 분류에서는 방향만 썼다.
- 반사실은 첫 1분만 바꾸고 이후는 학습 정글러가 둔다. "그 1분의 가치"이지 천상계 운영 전체의 가치가 아니다.
- 상대 9명은 모두 규칙 봇이다. 적 정글의 오브젝트 다툼을 늘려도 결과가 거의 안 변해서, 상대 가정보다는 시뮬레이터 결과 모델 쪽이 차이를 더 설명한다.

## 다음 단계에 넘길 것 (시뮬레이터 고칠 후보, 영향 큰 순)

1. 아이템을 교전·갱에 넣고 승률 모델이 구매 여부를 보게 하기(지금은 귀환 가치를 잴 수 없음). 1단계 데이터로 "같은 골드에서 아이템 골드 비중 → 다음 킬" 회귀 가능.
2. 라이너 딜교환 자리표시를 실제 체력 분포에 맞추기(위 값). 갱 보정(10분 KDA)을 다시 해야 함.
3. 카정 모델: 실제 카정 1분의 킬 관여 53%에 맞게 조우 교전 확률 낮추기, 적 정글러 위치를 안 상태의 카정 보상 확인.
4. 캠프 타이머 추정: 반사실에서 큰 영향은 없었지만 옮긴 상태의 정글 CS가 낮아, 비교 정확도를 올리려면 필요.

## 재현

```bat
:: PC (D:\AI\lol\ops-sim)
python tools\stage6_compact.py                 :: data\raw → data\stage6_compact.json.gz
:: 어디서나 (4코어 기준 시간)
python -m sim.compare situations               :: 약 4분, data\stage6_situations.json
python -m sim.compare outcomes --n 6000        :: 결과 모델 대조
python -m sim.compare counterfactual --per-cell 25 --reps 8          :: 약 30분
python -m sim.compare counterfactual --per-cell 15 --reps 6 --tag repeat
python -m sim.compare counterfactual --per-cell 15 --reps 6 --tag contest --set jungler.objective_go_prob=0.8
python -m sim.compare counterfactual --per-cell 15 --reps 6 --tag gank --set gank.coef.bias=-0.8
python -m sim.compare counterfactual --per-cell 15 --reps 6 --tag lanehp --set "laner.trade_damage=[0.01,0.08]" --set laner.hp_regen_per_s=0.003
python -m sim.compare counterfactual --per-cell 15 --reps 6 --tag camps --camp-shift 60
python -m sim.compare counterfactual --per-cell 15 --reps 6 --tag items --set gank.coef.item_gold_diff=0.35 --set skirmish.coef.item_gold_diff=0.35
python -m sim.compare report                   :: reports\stage6_compare.md, .json
```

가정 바꿈 실행은 각 약 13분. `gank.coef.item_gold_diff`, `skirmish.coef.item_gold_diff`는 기본 0(기존 동작 그대로)인 새 계수다.
